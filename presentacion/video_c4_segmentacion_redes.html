¿Todos tus contenedores en una Red Plana sin barreras?

En el Modelo C4, el Nivel 2 nos muestra los contenedores. El error más grave es poner todo en una sola red compartida: si vulneran la web, ¡tienen acceso total a tu base de datos!

Base de Datos Expuesta

Robo masivo de tablas y credenciales sin barreras.

Defensa en Profundidad Certificada

La Solución: Tres Redes Aisladas en Docker

Segmentamos el sistema para que cada contenedor solo hable con quien estrictamente necesita. ¡Si vulneran la web, la base de datos sigue 100% blindada e invisible!

1. Red Operaciones

bevadmin-ops-network
  • Traefik v3.2 (Ingress HTTPS :443)
  • CrowdSec WAF & IPS
  • Sondas Uptime Kuma
  • Autoheal Vigilante

2. Red Aplicación

bevadmin-app-network
  • dev-frontend (Angular 21 SPA)
  • dev-backend (Spring Boot 4)
  • Java 21 Loom Virtual Threads
  • Sin puertos públicos directos

3. Red Aislada Datos

bevadmin-data-network
  • dev-postgres (PostgreSQL 17)
  • Volúmenes Persistentes en Disco
  • Databasus & Copias Backup
  • ¡Zero Acceso a Internet!

Principios de Arquitectura Profesional

Las 3 Reglas de Oro de un Sistema Blindado

Aplica estos mandamientos en tus diagramas C4 y orquestaciones de Docker Compose.

1

Principio de Menor Privilegio

Ningún contenedor debe tener acceso a redes que no necesita. El frontend jamás habla con la base de datos.

2

Puerta de Entrada Única

Traefik centraliza certificados SSL y CrowdSec bloquea bots hostiles antes de que toquen tu código de negocio.

3

Bases de Datos Invisibles

PostgreSQL nunca debe exponer `ports: 5432:5432` a Internet. Solo comunicación interna en su red.
